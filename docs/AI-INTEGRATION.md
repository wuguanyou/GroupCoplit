# GroupPilot AI 接入架構

目前提供四條完整的模型工作流程：新增需求拆解、自然語言進度解析、重新分工建議、風險與貢獻分析。Groq 接入已完成虛構資料的真實呼叫驗證。AMD 仍待端點與授權；沒有設定就回傳 unavailable，不生成假資料。

## 流程

```text
AI 工作台 → POST /api/agent → 操作通行碼與配額檢查
  → 保存 running 工作（D1）→ 模型 JSON 回應
  → 結構／任務依賴／技能／工時驗證
  → 保存 proposed / clarification / complete / failed
  → 套用（或已授權自動執行）→ 再檢查專案版本
  → 既有任務工具與排程器 → 保存專案及 applied 紀錄
```

- 新任務只追加，不刪除或取代現有任務；每次最多 15 項、每專案最多 150 項。需先檢視再套用。
- 進度解析缺工時或可工作日期時，會要求補充。不得藉此完成成果驗收。
- 分工只能更改未完成／非待驗收任務，接手者需有技能及工時，排程不得因轉交變差（每次轉交計半天保守緩衝）。
- 成果證據、驗收與貢獻分數不授權給模型修改。
- 回報和重新分工可以勾選自動套用，但仍需團隊開啟自動分工且通過全部驗證。
- 專案版本變更後舊方案拒絕套用。requestId 防止相同請求重複呼叫模型；套用有專案內執行識別碼防止資料寫入成功但紀錄回覆失敗時重複执行。
- D1 原子預留控制同時一筆 90 秒內的 AI 工作及每日總量，失敗也消耗一次額度。不自動重試計費請求。模型請求上限 45 秒、6000 輸出 tokens、200 KB 回應。
- 工作紀錄保存在 agent_runs，前端讀取最近 20 筆；頁面離開仍保留紀錄。部署遷移必須先套用。

## AMD 接入準備

AMD 是算力／模型服務資源，不等於單一 API 協定。本版本預備 `chat`（OpenAI-compatible Chat Completions）及 `responses` 兩種傳輸方式；**不宣稱已驗證 AMD 的實際服務**。拿到 AMD-ITRI／官方雲端 LLM 文件後，確認端點可從網站後端透過 HTTPS 存取、認證方式、模型名稱及 JSON 輸出支援，再填設定。若官方服務協定不同，新增 adapter，不改任務工具與前端。

`AI_BASE_URL` 填 API base（例如官方提供到 `/v1` 的網址），不要附 `/chat/completions` 或 `/responses`。禁止將 API 金鑰放 query string、前端或 Git。

| 環境變數          | 用途                                                                                        |
| ----------------- | ------------------------------------------------------------------------------------------- |
| AI_ENABLED        | `true` 才允許呼叫                                                                           |
| AI_PROTOCOL       | `chat` 或 `responses`                                                                       |
| AI_BASE_URL       | AMD／模型服務官方提供的 HTTPS base URL                                                      |
| AI_MODEL          | 服務提供的模型識別碼，不自行猜測                                                            |
| AI_API_KEY        | 服務授權金鑰，只存在後端                                                                    |
| AI_OUTPUT_FORMAT  | 預設 `json_schema`；不支援嚴格 schema 但支援 JSON mode 時可用 `json_object`，仍保留本機驗證 |
| AI_OPERATOR_TOKEN | 另一組至少 24 字元的隨機操作通行碼，提供給測試操作者，不可與模型金鑰相同                    |
| AI_DAILY_LIMIT    | 每日模型請求上限，預設 20，可設 1–100                                                       |

本機設定在忽略版控的 `.env`；雲端設定在 Sites runtime secrets，更新後重新部署。`OPENAI_API_KEY`、`OPENAI_MODEL` 保留相容入口；明確設定上述 AI 變數為優先。

## 實測順序

1. 先在測試環境配置模型與操作通行碼，執行不修改資料的風險／貢獻分析。
2. 測試單一新需求拆解；核對工時估計及依賴，點選套用。
3. 用「還需 3 小時，三天後能做」測試進度解析及轉交。
4. 用缺少工時、無技能接手、模型斷線、過期版本與重複請求驗證不會誤寫。
5. 保存 AMD 服務連線證據、模型資訊與真實團隊評測，供競賽說明。

程式測試以注入的假 HTTP 回應驗證協定及安全性，**不是 AMD 模型品質或真實 API 連線驗證**。

## 目前邊界

網站已加入 ChatGPT 登入與專案成員授權；新專案從空白開始，AI 工作紀錄依專案隔離。AI 執行與套用限專案建立者，仍須操作通行碼。每日配額為全站共用以限制模型支出。檔案與成果身分綁定登入者，AI 目前不解析附件。排程只用每日工時，不含每週課表。定期追蹤仍由開啟頁面觸發；AI 工作台暫停該輪詢以避免提案被自動更新作廢。雲端排程、事件佇列、外部催辦尚未加入；不能宣稱已有 24 小時自主代理。

網站／資料庫維持 Sites。暫不需要 Railway 或新固定 IP；若 AMD 連線文件要求來源白名單，再配置符合需求的固定出口或跳台。
